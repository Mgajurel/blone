## Parent

`.docs/PRD.md` — Blone: a frictionless second brain

## What to build

Make categorization real, end-to-end: a save from a known domain gets its `type/` tag deterministically from URL rules; a save from an arbitrary domain gets exactly one model-guessed `type/` tag plus 2–5 freeform topic tags and a one-line summary, generated by Ollama under a custom tagging prompt. Ship the rule table (x.com/twitter.com → `type/tweet`, youtube.com/vimeo.com → `type/video`, news.ycombinator.com item pages → `type/article`, extensible as data), the custom prompt, and a scripted smoke test that pushes ~20 real URLs (mixed tweets, HN links, product pages, design pages) through the API and emits a quality report for human review — the PRD's accepted big-bang pressure valve.

## Acceptance criteria

- [ ] Rule-covered saves always carry the correct `type/` tag with no inference involved
- [ ] Non-rule saves get exactly one model-guessed `type/` tag from the closed set (tweet, article, product, design, video, link)
- [ ] Every enriched save carries 2–5 lowercase topic tags and a one-line summary
- [ ] The rule table lives as data (config), not code branches, and is documented for extension
- [ ] Smoke script exists: given a URL list, saves via API, waits for enrichment, and writes a report (per-URL: winning type, source of type, topic tags, summary) to `.docs/`
- [ ] Committed smoke report over ~20 real URLs, ready for the user's quality judgment
- [ ] The cloud escape hatch (flipping inference to a cloud model) is documented as a pure config change
